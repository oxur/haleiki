## What Worked

- Writing the render-smoke test *before* trusting the `| safe` discipline caught a
  real defect: minijinja's default auto-escape callback treats `.jinja` as an
  ignored suffix and falls back to `AutoEscape::None` for every template in this
  set. Without F-4's test, the whole escaping discipline would have shipped as a
  silent no-op (every field unescaped, not just the `| safe` ones). The fix
  (`set_auto_escape_callback` forcing `AutoEscape::Html`) is one line; finding it
  required actually rendering and asserting, not just wiring the loader.
- Testing against the real, already-authored `pages/about.jinja` and `base.jinja`
  (rather than inventing synthetic test-only templates) exercised the actual
  context contract fields (`about_intro`, `about_body`, `trust`) as the README
  documents them, and stayed inside the "no new route" boundary since no CLI/route
  wiring was added — only a template already on disk was rendered from a test.
- `env!("CARGO_MANIFEST_DIR")`-relative template paths in tests avoid coupling
  test correctness to the `cargo test` invocation's working directory.
